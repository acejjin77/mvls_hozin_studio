# MVLS HOZIN STUDIO — 비회원 수강신청 (1차)

구글폼 대신 홈페이지에서 바로 수강신청을 받고, 직원은 **구글 시트**에서 신청을 확인·관리합니다.
서버 없이 정적 HTML(GitHub Pages) + Google Apps Script 로 동작하며, 비용은 0원입니다.

```
방문자 ─ index.html (GitHub Pages) ──POST──▶ Apps Script 웹앱 ──▶ 구글 시트 'MVLS-신청내역'
                                                       └─▶ 직원 메일 알림 (선택)
```

## 파일 구성

| 파일 | 내용 | 누가 고치나 |
|---|---|---|
| `index.html` | 화면 구조 | 개발자 |
| `assets/style.css` | 디자인 | 개발자 |
| `assets/app.js` | 시간표·신청 로직 | 개발자 |
| `assets/config.js` | API 주소, 계좌, 카카오, 사업자 정보, 공지, 워크숍, 휴무일 | 운영 |
| `assets/classes.js` | **월별 시간표** (강사·시간·권종·금액·휴강·대강) | 운영 (매달) |
| `assets/terms.js` | 수강 안내·환불 규정, 개인정보 동의 문구 | 대표 확인 |
| `apps-script/Code.gs` | 접수 서버 (검증·중복 방지·시트 저장·메일 알림) | 개발자 |
| `assets/media/` | 메인 화면 수업 영상 3개(`class-1~3.mp4`)와 포스터 이미지(`.jpg`) | 운영 |
| `assets/img/` | 로고(`logo-black.png` 사용 중 · 어두운 배경용 `logo-white.png`), 파비콘, 링크 미리보기 이미지(`og-image.jpg`) | 개발자 |

디자인은 **흰 배경 + 검정 글씨**입니다. 색은 `style.css` 맨 위 `:root` 변수에서 바꿉니다. 노랑(`--accent`)은 버튼·선택 배경에만 쓰고, 흰 배경 위 강조 글씨는 진한 금색(`--accent-text`)을 씁니다. (노랑 글씨는 흰 배경에서 거의 안 읽힘)

`config.js` 의 `API_URL` 이 비어 있으면 **데모 모드**입니다. 실제 접수 없이 브라우저에만 저장되고, 푸터의 "데모 접수내역"으로 확인할 수 있습니다.

## 1. 접수 시트 + Apps Script (약 10분)

1. 스튜디오 구글 계정으로 새 구글 시트 생성 (예: `MVLS 수강신청`)
2. 메뉴 **확장 프로그램 → Apps Script** → 기본 `Code.gs` 내용을 지우고 `apps-script/Code.gs` 붙여넣기 → 저장
3. 상단 함수 목록에서 `setup` 선택 → **실행** → 권한 승인
   - 'MVLS-신청내역' 탭(상태 드롭다운·색상·필터)과 '수업별현황' 탭이 만들어집니다.
   - 예전 이름 '신청내역' 탭이 있으면 setup · 신청 · 조회 때 자동으로 'MVLS-신청내역' 으로 이름만 바뀝니다. (데이터 그대로, 시트에서 직접 바꿔도 됨)
4. (선택) **프로젝트 설정 → 스크립트 속성**에서 `NOTIFY_EMAIL` 에 알림 받을 메일 입력 (쉼표로 여러 개)
5. (선택) 함수 `testApply` 실행 → 시트에 테스트 행이 생기면 정상 → 그 행 삭제
6. **배포 → 새 배포 → 유형: 웹 앱**
   - 실행 사용자: **나**
   - 액세스 권한: **모든 사용자** (비회원 신청이므로 필요)
7. 발급된 `https://script.google.com/macros/s/…/exec` 주소를 `assets/config.js` 의 `API_URL` 에 붙여넣기
8. 시트 주소를 `ADMIN_SHEET_URL` 에 넣으면 푸터 '관리자' 링크로 연결됩니다. (시트 공유 설정으로 직원만 접근)

> **주의:** `Code.gs` 를 수정한 뒤에는 **배포 → 배포 관리 → 연필(수정) → 버전: 새 버전 → 배포** 해야 반영됩니다. "새 배포"를 다시 만들면 URL 이 바뀝니다.

배포 URL 을 브라우저로 열었을 때 `{"ok":true,"service":"mvls-apply","version":"…"}` 가 보이면 정상입니다. `version` 값이 `Code.gs` 상단의 `CODE_VERSION` 과 같아야 **최신 코드가 배포된 것**입니다. (편집기에서 저장만 하고 "새 버전"으로 배포하지 않으면 홈페이지는 계속 예전 코드를 사용합니다)

## 1-1. LAB 접수도 이 시트 파일에서 받기

LAB 홈페이지(mvls-lab)의 신청도 **이 스프레드시트 파일 · 이 Apps Script 프로젝트 · 이 웹앱 URL** 로 받습니다. 탭은 `LAB 신청내역` · `LAB 워크숍_…` 등으로 따로 쌓입니다. (학원은 `MVLS-신청내역`)

- 이 `Code.gs` 에는 LAB 연결 부분이 들어 있습니다: 요청에 `site=lab` 이 붙어 있으면 같은 프로젝트의 `Lab.gs` 로 넘깁니다. 그 외(학원 홈페이지 요청)는 지금까지와 똑같이 처리합니다.
- 설치: Apps Script 편집기 **＋ → 스크립트 → 이름 `Lab`** → mvls-lab 의 `apps-script/Lab.gs` 붙여넣기 → `setupLab` 실행 → **배포 관리 → 수정 → 새 버전** (URL 그대로)
- `Lab.gs` 가 없으면 학원만 동작하고, LAB 요청은 `LAB_NOT_INSTALLED` 로 거절됩니다. (학원 탭에 섞이지 않음)
- 배포 URL 을 열면 `"lab":"2026-11-22-lab-v4"` 처럼 LAB 버전도 함께 보입니다. (`null` 이면 `Lab.gs` 없음)
- 자세한 내용은 mvls-lab `README.md` 1장

## 2. 홈페이지 배포 (GitHub Pages)

1. 이 폴더(`mvls-web`)를 GitHub 저장소로 올림
2. **Settings → Pages → Branch: main / (root)** 저장
3. 도메인 연결 — 처음에는 **서브도메인**을 권장합니다. 리틀리 첫 화면은 그대로 두고 "수강신청" 링크만 새 페이지로 바꾸면, 문제가 생겨도 구글폼으로 바로 돌아갈 수 있습니다.
   - 가비아 DNS 관리: `CNAME` 레코드, 호스트 `apply`, 값 `<GitHub아이디>.github.io.`
   - 저장소 루트에 `CNAME` 파일 (내용: `apply.mvlshozinstudio.com`), Pages 설정에서 Enforce HTTPS 체크
   - 안정화 후 루트 도메인(`mvlshozinstudio.com`)을 리틀리에서 GitHub Pages 로 전환

## 3. 직원 운영 방법

- 새 신청은 'MVLS-신청내역' 탭 맨 아래에 **상태: 입금대기**로 쌓입니다. (메일 알림 설정 시 메일도 옴)
- 입금 확인 → 상태를 `입금확인` → 안내 메시지 발송 후 `확정`
- 그 외 상태: `대기`(정원 초과 대기), `취소`, `환불`
- 메모는 '관리자메모' 칸에. 필터로 강사·날짜·상태별로 볼 수 있습니다.
- '수업별현황' 탭: 수강시작일·수업별 신청 건수와 금액 합계 (취소·환불 제외), 상태별 건수
- 같은 연락처 + 같은 수업 + 같은 시작일은 중복 신청이 막힙니다. 취소 처리하면 다시 신청할 수 있습니다.
- 새 버전 배포 후 첫 신청(또는 `setup` 실행) 때 '인스타그램', '결제방식' 열이 **맨 오른쪽에 자동으로 추가**됩니다. 원하는 위치로 옮겨도 됩니다.
- **열 순서는 자유롭게 옮겨도 됩니다.** 저장할 때 1행의 헤더 이름으로 칸을 찾습니다. 단, 헤더 글자(예: `이름`, `연락처`)는 바꾸지 마세요. 열을 옮긴 뒤에는 Apps Script에서 `setup` 을 한 번 실행해야 '수업별현황' 탭 수식이 새 위치로 다시 만들어집니다.

## 3-1. 한국어 / 영문 신청 차이

| | 한국어 | 영문 (외국인) |

영문 완료 화면 하단 안내 문구는 `config.js` 의 `payment.notesEn` 에서 바꿉니다.

## 3-2. 신청내역 조회

홈페이지 상단 '신청내역', 메인 화면 '신청내역 조회' 버튼, 푸터 링크에서 열립니다.

- 한국어: **이름 + 연락처**, 영문: **이름 + 인스타그램 아이디** 가 모두 일치하는 신청을 최근 20건까지 보여줍니다. (이름의 띄어쓰기·대소문자는 무시)
- 보여주는 항목: 접수번호, 상태, 수업, 권종, 수강일, 금액, 결제방식, 신청일
- 보여주지 않는 항목: 연락처·인스타그램, 보호자 정보, 현금영수증 번호, 문의사항, 관리자메모
- 같은 연락처(인스타)로 10분에 10회, 전체 분당 40회까지 조회할 수 있습니다. (무작위 대입 방지 — `Code.gs` 상단 값으로 조정)
- 관리자메모는 조회 화면에 **노출되지 않으니** 자유롭게 써도 됩니다. 수강생에게는 '상태' 값이 그대로 보이므로 상태는 드롭다운 값만 사용하세요.

## 3-3. 보호자 연락처 판단 방법

신청자가 **만 14세 미만**이면 보호자 이름과 연락처를 받습니다. 외국인 보호자는 로밍이 안 돼 전화를 못 받는 경우가 많고, 국내 보호자도 이메일을 선호할 수 있어 **휴대폰 번호 · 이메일 · 인스타그램 아이디 중 하나**를 한 칸에 입력받습니다. 별도 컬럼으로 나누지 않고 시트의 **'보호자연락처'** 한 칸에 저장합니다.

### 판단 순서

입력값의 앞뒤 공백을 지운 뒤 **위에서부터 차례로** 검사하고, 처음 맞는 형식으로 저장합니다.

| 순서 | 형식 | 판단 기준 | 저장 형태 |
|---|---|---|---|
| 1 | 이메일 | 가운데 `@` 가 있고, `@` 뒤에 `.` + 2글자 이상 도메인이 있음 (100자 이내) | 소문자로 변환 |
| 2 | 전화번호 | `+` 또는 숫자로 시작하고 숫자·공백·`-` 만으로 이루어짐 | 국내 번호는 `010-1234-5678`, 국제 번호는 공백·`-` 제거 |
| 3 | 인스타그램 | 위 둘이 아니고, `@`·프로필 링크를 뗀 나머지가 영문·숫자·`.`·`_` 1~30자 | 소문자 + 앞에 `@` |
| - | (거절) | 셋 다 아님 | 신청 불가, 안내 문구 표시 |

- 전화번호 유효 조건: 국내 휴대폰 `01X` + 7~8자리, 또는 `+` 로 시작하는 국제번호 8~15자리
- 숫자로만 된 인스타그램 아이디는 전화번호로 판단되므로, 이런 경우 보호자에게 `@` 를 붙여 입력하도록 안내하세요. (`@` 로 시작하면 숫자만 있어도 인스타그램으로 처리)

### 입력 예시

| 입력 | 판단 | 시트에 저장되는 값 |
|---|---|---|
| `01055556666` | 전화번호 | `010-5555-6666` |
| `010-5555-6666` | 전화번호 | `010-5555-6666` |
| `+1 415 555 0100` | 전화번호 (국제) | `+14155550100` |
| `+82-10-1234-5678` | 전화번호 (국제) | `+821012345678` |
| `Mom@Example.com` | 이메일 | `mom@example.com` |
| `@Dad_IG` | 인스타그램 | `@dad_ig` |
| `instagram.com/dad_ig` | 인스타그램 | `@dad_ig` |
| `https://www.instagram.com/Dad_IG/?hl=en` | 인스타그램 | `@dad_ig` |
| `dad_ig` | 인스타그램 | `@dad_ig` |
| `john@gmail` | 거절 (도메인 끝 없음) | - |
| `12345` | 거절 (전화번호 자릿수 부족) | - |
| `a b c` | 거절 (공백 포함) | - |

### 코드 위치

같은 규칙이 화면과 서버 두 곳에 있습니다. **규칙을 바꿀 때는 두 곳을 함께 수정**하고, `Code.gs` 는 새 버전으로 다시 배포하세요.

| 위치 | 함수 | 역할 |
|---|---|---|
| `assets/app.js` | `normContact()` | 입력 즉시 검사 · 오류 안내 (사용자 편의) |
| `apps-script/Code.gs` | `normContact_()` | 시트 저장 전 최종 검사 · 정리 (실제 기준) |

화면 검사는 우회될 수 있으므로 **서버(`Code.gs`)의 판단이 최종 기준**입니다.

## 4. 매달 시간표 바꾸기

`assets/classes.js` 만 수정합니다. 수업 하나가 객체 하나입니다.

```js
{
  id: 'MON-1820-TORCH',        // 영구 식별자 — 기존 수업은 바꾸지 말 것
  business: 'ACADEMY', day: 1, start: '18:20', end: '19:40',
  instructor: 'TORCH', title: 'STEP UP', genre: 'house',
  tickets: [{ type: '4W', weeks: 4, price: 150000 }, { type: '1T', price: 40000 }],
  closures: ['2026-11-30'],    // 휴강
  subs: [{ date: '2026-11-16', by: 'COCO' }],   // 대강
  // period: { from, to }  기간제 특강   /  dates: [...] 특정일만  /  startsFrom  첫 수업일  /  open: false 온라인 신청 막기
}
```

- 휴강·대강을 넣으면 상단 공지, 시간표, 날짜 선택에 자동 반영됩니다.
- 지난 날짜, 수업 시작 시각이 지난 오늘 수업, 휴강일은 선택할 수 없습니다.
- 기간제 수업의 n주권은 **기간 안에 n회가 모두 들어가는 시작일만** 선택할 수 있습니다. 남은 회차가 부족하면 1회권만 열립니다.
- 시작일 선택 범위는 오늘부터 `bookingWindowWeeks`(기본 6주)입니다.

## 4-1. 메인 영상 바꾸기

메인 화면은 영상 3개를 **각 10초씩 재생 → 옆으로 슬라이드 → 무한 반복**합니다. 화면 밖으로 스크롤하거나 다른 탭으로 가면 멈추고, 우측 상단 버튼으로 일시정지할 수 있습니다.

새 영상으로 바꿀 때는 원본을 그대로 올리지 말고 10초로 잘라 압축해서 **같은 파일 이름**으로 덮어씁니다. (아이폰 원본은 수십~수백 MB라 페이지가 느려지고, GitHub는 100MB 넘는 파일을 거부합니다)

```bash
# 원본.MP4 의 12초 지점부터 10초, 세로 720x1280, 소리 없음
ffmpeg -ss 12 -i 원본.MP4 -t 10 -an \
  -vf "scale=720:1280:force_original_aspect_ratio=increase,crop=720:1280,fps=30,format=yuv420p" \
  -c:v libx264 -preset veryfast -crf 27 -maxrate 2.6M -bufsize 5M -movflags +faststart assets/media/class-1.mp4
# 포스터(첫 화면) 이미지
ffmpeg -ss 0.3 -i assets/media/class-1.mp4 -frames:v 1 -q:v 5 assets/media/class-1.jpg
```

영상 개수를 바꾸려면 `index.html` 의 `reel__slide` 와 `reel__bar` 를 같은 개수로 추가·삭제하면 됩니다.

## 5. 오픈 전 확인할 항목

코드에 `[확인 필요]` 로 표시해 두었습니다.

1. **환불 규정·개인정보 동의 문구** (`terms.js`) — 현재 구글폼의 수강 안내 이미지 원문으로 교체하고 대표 확인. 보유 기간도 확정.
2. **학원 등록번호·사업자등록번호** (`config.js` businesses) — 학원 홈페이지 표시 의무 항목 (명세서 20.1 A-3)
3. **휴강 시 4주권 연장 여부** (`extendOnClosure`, 명세서 B-5) — 현재는 휴강 주를 건너뛰고 1주 연장해 수강 예정일을 보여줌
4. **공휴일 휴무** (`holidays`) — 12/25, 1/1 운영 여부
5. 시간표 ↔ 구글폼이 서로 다른 부분
   - BROTHER BIN `LOCKING TRAINING`(수) — 시간표에는 있지만 구글폼 신청 목록에 없음 → 현재 "온라인 신청 준비 중"
   - SEONG HEE(금) — 시간표 이미지는 "하우스 Starter", 구글폼·공지는 "HIPHOP Starter" → HIPHOP 으로 입력
   - QUIIIDY 시작일 — 월등록폼 11/10, 1회권폼 11/12 → 목요일인 11/12 로 입력
   - SIMMON·QUIIIDY 종료 시각 — 시간표 22:20, 월등록폼 22:30 → 시간표 기준
   - HAN SMASH 기간 시작일 미기재, 5000 HARD TRAINING 2회 전체권 금액 미기재
6. 1회권 40,000원 / 4주권 금액이 교육청에 등록된 교습비와 일치하는지 (명세서 A-3)
7. 14세 미만 수강생 여부 — 보호자 정보·동의 입력란은 넣어두었음 (명세서 A-4)
8. `index.html` 의 `og:image` 주소 — 카카오톡 링크 미리보기용. 지금은 GitHub Pages 기본 주소(`acejjin77.github.io/mvls_hozin_studio`)로 되어 있으니 다른 도메인·호스팅을 쓰면 그 주소로 변경

## 6. 알아둘 한계 (1차 범위)

- **금액은 화면 기준으로 저장**됩니다. 서버가 수업 목록을 모르기 때문에, 조작된 금액이 들어올 수 있습니다. 실제 입금액과 대조해 `입금확인` 처리하는 지금의 운영 방식이 이를 보완합니다. (2차: 시간표를 시트에서 관리하면 서버에서 금액 검증 가능)
- 정원·잔여석 관리 없음 (명세서 B-6 정책 확정 후)
- 신청자에게 자동 문자/알림톡 없음 — 기존처럼 직원이 안내 (명세서 6.2, Make Edu API 확인 후)
- Apps Script 응답은 2~4초 걸릴 수 있습니다. 같은 신청을 두 번 눌러도 요청 ID 로 한 건만 저장됩니다.
- 신청 정보는 구글 시트(국외 서버)에 저장되므로 개인정보 동의문에 국외 이전을 명시했습니다.
